# Publish meeting notes to notes.harrywaterman.com — Design

**Date:** 2026-07-17
**Status:** Approved

## Goal

From the Meeting Notes TUI, manually publish a meeting's summary note as an
unlisted web page at `https://notes.harrywaterman.com/n/<slug>`, copy the link,
and be able to unpublish it later. "Unlisted" means: anyone with the link can
view it, but links are unguessable and nothing enumerates them.

## Requirements (settled during brainstorming)

- **Access:** anyone with the link; no index page, no listing, unguessable URLs.
- **Content:** summary only — the existing note markdown (which already excludes
  the transcript), minus local-only frontmatter/footer.
- **Trigger:** manual, per note, from the TUI. Nothing uploads automatically.
- **Lifecycle:** upload + delete (unpublish). No edit/re-upload flow for v1;
  pressing upload on an already-published note just re-copies its link.
- **Hosting:** the existing harrywaterman.com is a static Next.js export on
  GitHub Pages with no backend; `notes.harrywaterman.com` has no DNS record yet.
  DNS is at Hover. Harry has an existing AWS account.

## Approach chosen

**S3 + CloudFront** (over GitHub Pages, which makes note content enumerable in
a public repo and adds minutes of publish latency; and over Cloudflare
Workers, which would require moving the DNS zone off Hover).

## Architecture

### Infrastructure (one-time, scripted)

- S3 bucket, all public access blocked, no listing. Objects live at key
  `n/<slug>` (no extension) with `Content-Type: text/html`, giving clean URLs
  with no directory-index handling.
- CloudFront distribution with Origin Access Control reading the bucket,
  alternate domain `notes.harrywaterman.com`, ACM certificate in `us-east-1`
  (DNS-validated).
- `cloud/setup.sh` in this repo: idempotent AWS CLI script (mirroring the
  `gnome/install.sh` style) that creates bucket, cert, OAC, and distribution,
  then prints the two records to add at Hover: the ACM validation CNAME and
  `notes → <distribution>.cloudfront.net`.
- Root path serves a minimal placeholder/404 page; `robots.txt` disallows all;
  every note page includes `<meta name="robots" content="noindex">`.
- 404/AccessDenied from S3 maps to a plain 404 page via CloudFront custom
  error response.

### App-side component: `meeting_notes/uploader.py`

`NoteUploader`, constructed from `AppConfig` like the other pipeline
components. Responsibilities:

- **Render:** read the note `.md`, strip YAML frontmatter and the local-only
  footer lines (the "Press 't'" / "Generated by" block), convert markdown to
  HTML with the pure-Python `markdown` package, and wrap it in a
  self-contained template: inline CSS, no external assets, `noindex` meta,
  title/date/duration header from the note.
- **Slug:** `secrets.token_urlsafe(16)` (128 bits).
- **Upload:** `put_object` via boto3 to `n/<slug>` with
  `Content-Type: text/html; charset=utf-8`. boto3 is imported lazily inside
  the method (faster-whisper pattern). Both `boto3` and `markdown` go in a
  new optional extra (e.g. `[upload]`, also folded into `[all]`); `markdown`
  is lightweight, so CI adds it to its install step to run the render tests,
  while the fake-boto3 injection keeps boto3 itself out of CI.
- **Delete:** `delete_object` for the slug parsed from the note's `share_url`.
- Credentials come from the standard boto3 chain (env/`~/.aws`); no keys in
  the app config file.

### Config

New `AppConfig` fields (config-file only for v1 — no settings-screen UI):

- `upload_bucket: str = ""` — empty means the feature is off.
- `upload_region: str = "us-east-1"`
- `upload_base_url: str = "https://notes.harrywaterman.com"`

`validate_config()` rejects a malformed `upload_base_url`; the TUI action
notifies "uploads not configured" when `upload_bucket` is empty.

### Tracking published notes

The share URL is written into the note's own YAML frontmatter as
`share_url: "https://notes.harrywaterman.com/n/<slug>"`. The frontmatter is
the single source of truth: it survives file renames (edit-title), travels
with Obsidian exports, and is user-visible. Unpublishing removes the key.
Frontmatter editing preserves all other keys and body content byte-for-byte.

### TUI integration (`app.py`)

- `u` — upload selected note. If `share_url` already present, copy the
  existing link instead of re-uploading. On success: write frontmatter,
  copy URL to clipboard (existing clipboard helper), notify.
- `U` — unpublish. Confirmation prompt (link dies immediately), then S3
  delete + frontmatter key removal + notify.
- Both run as `@work(thread=True)` workers; all UI updates go through
  `self.call_from_thread(...)`, matching `process_recording`.

## Error handling

- Upload/delete failures (network, credentials, missing bucket) are
  **non-fatal**: a notification with a short reason; the note is untouched.
  Retry is manual (press `u` again). No retry queue.
- Missing boto3 → notification with the pip install hint, not a traceback.
- Frontmatter is only written after a successful PUT; delete removes the S3
  object first and only then edits frontmatter, so a failed delete leaves the
  link intact and visible rather than orphaned-but-believed-dead. An S3
  "NoSuchKey" on delete is treated as success (already gone).

## Testing

- New lightweight test file (added to the explicit CI list in
  `.github/workflows/ci.yml`) with a **fake boto3 injected into
  `sys.modules`** before import, per the fake-faster-whisper pattern:
  - render: frontmatter and footer stripped, HTML self-contained, noindex
    present, markdown converted.
  - slug generation shape/length.
  - frontmatter `share_url` add/read/remove round-trip preserves other content.
  - upload flow: correct key/content-type; failure → no frontmatter write.
  - delete flow: S3 delete before frontmatter removal; NoSuchKey tolerated.
- `cloud/setup.sh` is exercised manually (AWS side), not in CI.

## Out of scope (v1)

- Automatic upload, per-note visibility choices, edit/re-publish, an index or
  auth, settings-screen UI for the new config fields, styling parity with
  harrywaterman.com beyond a clean minimal page.
