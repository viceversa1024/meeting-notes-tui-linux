# GNOME Integration for Meeting Notes TUI

**Date:** 2026-07-15
**Status:** Approved

## Goal

Give GNOME users the same integration the repo already ships for Hyprland/Waybar:
a top-bar recording-status indicator and a global keybind that launches the app.
Everything lives in a new `gnome/` directory mirroring the existing `hyprland/`
directory, and reuses the `.status` file the app already writes
(`STATUS="idle|recording|processing"`, plus `TITLE` and `DURATION` while recording,
updated every second at the repo root).

Target environment: GNOME Shell 47 on Ubuntu (Wayland) with the stock
`ubuntu-appindicators` extension enabled. All dependencies (PyGObject,
AyatanaAppIndicator3 typelib) are preinstalled system packages; the indicator
runs on `/usr/bin/python3`, NOT the project venv.

## Components

### 1. `gnome/meeting-notes-indicator.py`

A standalone AppIndicator script (system python3, PyGObject +
AyatanaAppIndicator3). No dependency on the `meeting_notes` package.

- Locates the repo root as the parent of its own directory (same auto-detect
  pattern as `hyprland/waybar-module.sh`) and reads `<repo>/.status`.
- Polls every 2 seconds via `GLib.timeout_add_seconds`. Each tick it also
  checks whether the app process is running (equivalent of
  `pgrep -f "python.*run.py"`).
- States and presentation:
  - **Not running** (no app process): dim/idle microphone icon, no label.
  - **Ready** (app running, `STATUS="idle"` or missing file): normal
    microphone icon.
  - **Recording**: record icon (red where the theme allows) with the live
    `DURATION` (e.g. `05:42`) as the top-bar label; tooltip shows `TITLE`.
  - **Processing**: sync/processing icon.
- Menu items: **Open Meeting Notes** (invokes `~/.local/bin/meeting-notes`),
  **Open notes folder** (`xdg-open <repo>/notes`, the app's default
  `notes_dir`), **Quit indicator**.
- Status-file parsing lives in a small pure function (parse the
  `KEY="value"` lines into a dict) so it is unit-testable without GTK.
- Parsing errors or a malformed `.status` degrade to the "ready" state;
  the indicator never crashes on bad input.

### 2. `~/.local/bin/meeting-notes` launcher (generated by installer)

- Runs `kitty --class meeting-notes` executing `venv/bin/python run.py` in the
  repo directory.
- Already-running guard: if the app process is already alive, send a desktop
  notification ("Meeting Notes is already running") via `notify-send` instead
  of spawning a second instance — two instances would fight over audio capture
  and the config.

### 3. `gnome/install.sh`

Idempotent installer (safe to re-run):

- Writes the launcher script to `~/.local/bin/meeting-notes` (0755).
- Registers the global keybind **Ctrl+Alt+M** → the launcher, via `gsettings`
  custom keybindings. Appends a new entry to the existing
  `custom-keybindings` list without clobbering other entries; if our entry
  path already exists, updates it in place.
- Installs `~/.config/autostart/meeting-notes-indicator.desktop` pointing at
  `/usr/bin/python3 <repo>/gnome/meeting-notes-indicator.py`.
- Starts the indicator immediately (if not already running).
- Prints what it did.

### 4. README

New "GNOME Integration" section alongside the existing Hyprland/Waybar one:
what the indicator shows, how to run `gnome/install.sh`, the keybind, and how
to uninstall (remove launcher, autostart file, and the gsettings entry).

## Error handling

- Indicator: missing `.status` → "ready" if app running, "not running"
  otherwise; unreadable/garbled file → "ready"; missing icon names fall back
  to a generic icon. Never raises out of the poll callback.
- Launcher: missing kitty → `notify-send` error message.
- Installer: fails loudly with a message if `gsettings` or the schema is
  unavailable; never writes a malformed keybindings list.

## Testing

- **Unit (pytest, TDD):** the `.status` parse function — valid recording
  state, idle, missing keys, garbage input, empty file.
- **Live verification on this machine:** run the installer; confirm the
  keybind launches the TUI in kitty; write synthetic `.status` states and
  confirm the indicator icon/label updates; confirm the already-running guard
  notifies instead of double-launching; re-run installer to confirm
  idempotency.

## Out of scope

- GNOME Shell extension (rejected: version-pinned GJS, more maintenance for
  marginal visual gain over an AppIndicator).
- Focus-existing-window on second launch (Wayland GNOME restricts
  programmatic window activation; the guard notification is the fallback).
- Changes to the app's `.status` writing (format stays exactly as the Waybar
  module expects).
